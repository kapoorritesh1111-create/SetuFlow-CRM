BEFORE YOU START
Prerequisites
1. All open Critical/High issues from the tracker must be resolved before running a full E2E suite. Check the issue tracker for open items.
2. Ensure the production DB has test data: ≥1 org, ≥1 user, ≥2 products with pricing, ≥1 lead, ≥1 quote, ≥1 order.
3. Use a dedicated test account with Admin role — not your personal account.
RUNNING A STEP
How to test each step
1. Open the CRM at the route shown on the step.
2. Perform the action described in the "What to do" field.
3. Compare the result to "Expected result".
4. Mark Pass, Fail, or Skip.
5. On Fail: expand the step → add a note describing what actually happened → upload a screenshot → click "File Bug" to report to issue tracker.
EVIDENCE RULE
Always capture screenshots
For every Fail: a screenshot is required before filing a bug. This gives developers exact reproduction context.
For PDF checks: screenshot the opened PDF even on Pass — it proves what was generated at the time of testing.
Files upload to the qa-evidence Supabase Storage bucket and are linked to this run.
FILING BUGS
Bug goes to live tracker
Click "✗ Fail" on a step → expand → "File Bug" button → fill the modal → submit. The bug is inserted directly into sprint_issues in Supabase, visible in the issue tracker immediately. Check the issue tracker after testing to confirm all filed bugs are visible.
COMPLETING A RUN
Mark complete when done
After running all steps, click "↓ Export" to download a text report. The run record in the database is automatically updated with pass/fail counts as you test. Past runs show in the sidebar for reference.
Key principle from docs: Work should move Lead → Quote → Approval → Order → Documents → Packing → Dispatch → Closeout. Testing must verify each gate actually enforces its requirements. Do not verify gate enforcement by reading the UI label — actually try to bypass it and confirm it is blocked.
STAGE 1
Capture
Business card scan or vCard form creates a lead draft for operator review. Lead must not become a commercial record without operator approval.
/contact-exchange/scan
STAGE 2
Follow-up / Qualification
Qualify the lead, map product interests, confirm buyer country and market, check compliance posture. Quote prep checklist must be green before proceeding.
/leads
STAGE 3
Quote Build
Versioned quote with catalog line items, FX rate, Incoterms, payment terms, and validity. Sent quote version is immutable — never mutate, always create new version.
/quotes
STAGE 4
Approval & Send
Compliance gate → approval if required → send via email or WhatsApp. link_created ≠ delivered. Track opens separately.
/approval-send
STAGES 5–12
Order Execution
Actual Lines → Buyer Document → Packing → Freight Queue → Processing → Delivery Note → Final Invoice → Paid & Closed. Eight stages, each gated. No stage can be skipped.
/orders
Immutability rule: Sent/accepted quote versions CANNOT be mutated. Order changes go into order_lines — never by editing an accepted quote version. If you need to change terms, create a new quote version.
QUOTE PDF ✅
The working reference
Quote PDF is the reference implementation. Must contain: SETU Flow logo, org legal name, registered address, Tax ID, contact email (SELLER box), buyer identity (BUYER box), line items with HS codes, pricing basis, T&C section with 5+ numbered clauses, signature blocks.
ORDER PDFs ⚠️
Check fix status first
SF-23-003/004 may still be open. Check issue tracker before testing. For Order Confirmation and Invoice PDFs: verify SELLER/EXPORTER box has real org data. If empty → bug still open → mark FAIL with screenshot. Payment terms must NOT say "Payment per terms" placeholder.
TEST METHOD
How to test every PDF
1. Open PDF in browser (click download link).
2. Screenshot the full first page.
3. Check every required field against the expected list.
4. Scroll to bottom — confirm T&C section.
5. Upload screenshot as evidence regardless of pass/fail.
EMPTY ORDER
Guard test (SF-23-010)
Create an order, don't add line items, try to generate PDF. Expected: API returns error "No line items found". Broken behavior: PDF downloads with "Order line pending" placeholder row at USD 0.00. If broken → mark FAIL → file bug.

COMPLIANCE GATE
Blocks quote send
A red compliance item (status open or needs_review) blocks the quote send workflow. Test: add a compliance blocker to a lead → try to send quote → confirm send button is disabled or shows blocker message. Cannot pass compliance gate without resolving blockers.
ORDER STAGE GATES
No stage skipping
Each order stage requires the previous stage to be approved. Test: try to advance from Actual Lines to Buyer Document without approving actual lines. Gate must block with an explanation. "Force advancing" by URL manipulation should not work — gates are server-side.
APPROVAL GATE
Requires admin role
Quote approval requires a user with approval permission. Test as a non-admin user: the "Approve" action should not be available or should fail with a permission error. Only admin/owner roles can approve quotes.
RLS — DATA ISOLATION
Cross-org data never visible
Every query must be filtered by organization_id. Test: create two org accounts if possible, log into org A and confirm org B data is not visible anywhere in the UI. No cross-org data should ever appear.
Immutability: Sent/accepted quote versions must NEVER be mutated. If you discover the system allows editing an accepted quote version's line items — file a Critical bug immediately. This is a commercial data integrity violation.
