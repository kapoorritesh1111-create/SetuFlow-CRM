2.2 Quote & Quote Versioning Workflow

Version policy: current_version_id → active working version. accepted_version_id → buyer-accepted/order-source version. These must NEVER be confused.
🔄 Version States
  • Draft — editable working version
  • Needs approval — pending before send
  • Sent — customer-facing, locked
  • Accepted — buyer accepted this version
  • Order source — execution order created
  • Superseded by vN — older, has newer version
📌 CTAs
Create quoteCreate quote with cautionAdd productSave draftSend quoteOpen customer PDFMark acceptedMark rejectedApprove & allow send
🚫 Blockers
Missing lead/currency/linesApproval pendingCompliance evidence missingNo FX snapshotNo current version
Rule CategoryDetail
Data Truthquotes = header/current-status. quote_versions = immutable commercial version once sent/accepted. quote_version_line_items = line-item source of truth.
PersistenceDraft/new → quotes + version + line tables. Send updates quotes.sent_at, quotes.sent_version_id, quote_versions.status.
ImmutabilityEditing a sent/approved/accepted/rejected/expired/order-source quote must create a NEW quote version. Earlier versions remain readable for audit.
Send GateRequires: quote.send permission, current version, line count, approval readiness, no active send blockers.
Integration BoundaryEmail/WhatsApp send tracking is internal unless a provider connector confirms delivery. link_created ≠ delivered.
AuditSend-blocked decisions recorded. Send/outcome events through communication, negotiation, activity, and audit paths.
Quote PDF PolicyLight white/slate layout. Shows: SKU, Product, Pack (g), Units/Case, MOQ cases, Basis, Selected currency per unit/case, Line total. Must not hardcode USD when quote is in AUD/EUR/GBP/INR.
Share Link PolicyMust use production-domain buyer-facing pages from https://www.setuflowcrm.com. Never expose Vercel preview URLs. Must show org logo when available.

2.4 Support Workflows

📦 Product Setup
  • Admin → Categories (parent first, then child)
  • Set category-level pricing defaults
  • Products workspace → Add Product
  • Add Variants (pack size, UOM, MOQ)
  • Set Pricing (starting level, cost layers, margins)
  • Bulk import via CSV (Categories → Products → Pricing)
👥 User Onboarding
  • Admin → Invitations → Enter email + role → Send
  • User clicks link → creates password → lands in workspace
  • Admin → Users → Verify role is correct
  • User sets up Profile → My Card → vCard
  • TodayBar shows assigned leads needing action
🎪 Trade Events
  • Admin → Trade Events → Create event
  • Assign team members; confirm scan readiness
  • During event: Business Card Scan or Quick Entry
  • Share vCard via QR or link
  • Post-event: filter leads by Source Event
  • AI Suggestions may draft follow-up messages
📋 Compliance & Documents
  • Document Blocker = required doc not uploaded
  • Compliance Blocker = checklist item unresolved
  • Attach evidence → Waive for quote → Defer to dispatch
  • Waivers require human reviewer reason
  • Resolve = Compliance Assist from lead/quote context
💱 FX & Pricing
  • USD identity handled automatically
  • Manual FX can be allowed by settings
  • Non-USD requires exchange_rates snapshot
  • Override requires reason; may trigger approval
  • Pricing rule sets cascade: org → category → product
🤖 AI Suggestions
  • AI drafts follow-up emails, cover notes, summaries
  • AI does NOT set prices, approve quotes, or send messages
  • AI does NOT advance order states or make compliance decisions
  • Always review and edit before using a draft
  • Dismiss or provide better lead context to improve quality

Click-By-Click Operator Guides

Guide 1: Lead to Quote

1
Click Follow-up in main navigationExpected UI: Lead queue loads from leads. Expected data: All org leads visible per RLS policy.
2
Click Open on the lead rowExpected UI: Lead Command Center opens with workflow cards (qualification, coverage, follow-up, compliance). Verify lead has buyer/supplier context and is not disqualified.
3
Click Open coverage manager if product coverage is missingSelect product interest → Save. Expected data: lead_product_interests row created. Quote CTA becomes dominant when gate passes.
4
Click Plan follow-up if next action is missingEnter follow-up date and note. Expected data: lead_follow_ups row written.
5
Check compliance card for any quote-send blockersIf red: click Compliance check or Full screen. Choose one: Attach evidence, Waive for quote (with reviewer reason), or Defer to dispatch.
6
Click Create quote or Continue quoteVerify: lead not disqualified, product interest exists, country/market set, compliance posture acceptable.
Do NOT: Treat a free-text product note as saved product coverage. Do NOT bypass compliance by creating a disconnected quote. Do NOT assume WhatsApp/email activity means delivery was confirmed.

Guide 2: Quote Build and Send

1
Click Quote in navigation or open from leadSelect/create quote for the correct lead. Expected data: Draft quote_versions record exists or will be created.
2
Click Add product and select catalog productsSystem loads pack size, MOQ, pricing basis defaults from catalog. Verify each line has product, quantity, unit, price.
3
Confirm currency, pricing basis, validity, incoterm, freight profileFor non-USD: verify FX snapshot exists or manual FX is enabled. Expected: FX context recorded in quote_pricing_snapshots.
4
Review pricing and enter override reasons for any manual changesOverride >15% triggers pending approval. Expected data: Approval flag set on quote_versions.
5
Click Save draft or Create quoteExpected data: quotes, quote_versions, quote_version_line_items, quote_pricing_snapshots all written.
6
Resolve any approval/compliance blockersIf approval pending: owner/admin approves from Quotes workspace approval queue. If compliance blocker: use Step 4 → Review card inside quote workspace.
7
Click Send quoteExpected data: quotes.sent_at set, quote_versions.status = 'sent', communications row created. Quote is now LOCKED from direct editing.
8
Click Open customer PDF to review outputVerify: org logo, correct currency, all line items, incoterm/payment terms, tax ID visible.
9
Record buyer outcome: Mark accepted or Mark rejectedOnly after actual buyer response. Expected data: quotes.accepted_version_id set on acceptance.

Guide 3: Accepted Quote to Order

1
In /quotes, open a sent quote → Click Mark acceptedExpected data: quotes.accepted_version_id set; contract/order handoff RPCs called; orders record created.
2
Navigate to /orders → Click Open on the new orderExpected UI: Order workspace shows stage strip. Stage 1 = "Quote Approved". Verify orders.source_quote_id and source_quote_version_id are set.
3
Click Prepare actual linesExpected: System seeds order_lines from accepted quote/contract. Gate status set to "prepared". Quote version lines remain UNCHANGED.
4
Review quote vs actual lines. Save quantity/price/reason for any differencesExpected data: order_lines rows reflect actual order. Changes stored with reason fields. quote_version_line_items remain unchanged.
5
Click Approve actual linesExpected data: order_approval_gates entry approved; order_stage_events written; order moves to Internal Approval stage.

Guide 4: First Document and Send Tracking

1
Open the order → Stage: "Internal Approval" → Click Prepare documentSystem creates order document draft. Type: proforma_invoice (export) or order_confirmation (regional).
2
Click Preview → Review the rendered documentCheck: product, quantity, price, parties, incoterm, terms, org logo, tax IDs, bank details. Expected: Preview route opens, open count tracked.
3
Click ApproveExpected data: order_documents.status = 'approved'. Gate approved. Non-preview sends now permitted.
4
Click Send tracked → Select channel (Email/WhatsApp) → Verify recipientExpected data: order_document_sends row created with status = 'link_created'. Recipient defaults from lead contact info.
5
Use Download / Print PDF if a file is neededOpens browser print dialog. Expected: toolbar hidden from PDF output. Note: This is browser-print, not server-generated PDF binary.
Critical: link_created ≠ delivered. Do NOT treat a tracked link as confirmed email/WhatsApp delivery. Do NOT send unapproved documents to buyers.

Guide 5: Packing, Freight & Trade Requirements

1
Open order after first document approval → Click Prepare packing sheetExpected data: packing_plans and packing_plan_lines created. Based on actual order lines.
2
Click Preview packing sheet → Click Approve packing sheetExpected: Packing stage complete. Processing and freight request actions now unlocked.
3
Click Prepare freight requestConfirm: origin, destination, incoterm, packing basis. Expected data: freight_rate_requests created.
4
Search and attach trade requirements → Click Confirm sourceExpected data: trade_requirements and trade_requirement_sources rows created. No rule match = human review, NOT automatic clearance.
5
Resolve all blocking trade requirements before dispatchBlocking severity requirements must be reviewed by a human. Dispatch blocked until clear.

Guide 6: Processing, Dispatch & Closeout

1
Open Processing stage → Save picked/packed/QC checksMark: Picked ✓, Packed ✓, QC Passed ✓. Add notes for exceptions. Expected data: order_processing_checks metadata written.
2
Complete processing only when all three checks passExpected: Delivery note and logistics unlocked. Processing gate approved.
3
Approve logistics documents → Click Create shipment draftEnter: shipment mode, carrier, forwarder, booking/tracking reference. Expected data: shipments draft record created.
4
Resolve all blocking trade requirements → Click Approve dispatchExpected data: shipments.status = 'dispatched'. Order stage moves to Dispatch/Invoice.
5
Prepare/Preview/Approve final invoice → Click Approve invoiceExpected: Final invoice document approved. Note: Final invoice must reflect actual dispatched quantities, NOT quoted quantities.
6
Enter payment reference, reconciliation confirmation, outstanding amount = 0, archive confirmation → Click Generate receipt + closeExpected data: orders.status = 'completed'. finance_sync_records written. Closeout gate approved.

Key Blockers

  • Compliance evidence missing
  • No FX snapshot
  • No current version or line items
  • Send blocker flag active

  • Quote has line items

  • FX snapshot exists for non-USD

  • Sent quote is IMMUTABLE
  • Share links = production domain only
Quote Versioning
Goal: Keep quote history clean and auditable

Version States

  • Draft — editable
  • Needs approval — blocked
  • Sent — LOCKED
  • Accepted — LOCKED → order source
  • Rejected — LOCKED
  • Superseded by vN

Key Rules

  • Revise instead of editing locked versions
  • current_version_id ≠ accepted_version_id
  • Orders start from accepted_version_id only
  • Earlier versions stay readable

Documents + System

  • Quote PDF from structured version data
  • Share page shows org logo when configured
  • quote_pricing_snapshots preserve FX context
  • parent_version_id links revision chain

  • Approve actual lines

  • Download / Print PDF

Key Blockers

  • No accepted quote lineage
  • Actual lines not approved
  • Document not approved before external send
  • Packing not approved before freight
  • Processing incomplete before dispatch
  • Blocking trade requirements open

Key Documents

  • Proforma invoice (export)

  • Send again

System Rules

  • Parent order_documents not overwritten
  • open_count increments per link access
  • Channel defaults from lead contact info
  • Blank recipient → manual entry required

Goal: Close the order after invoice, payment, reconciliation, and archive

Key CTAs

  • Prepare final invoice

  • Download archive

Key Blockers

  • Payment not received
  • Reconciliation incomplete
  • Outstanding amount above zero
  • Archive not confirmed

System Rules

  • Final invoice ≠ proforma invoice
  • Final invoice = actual dispatched quantities
  • Finance sync NOT automatic (adapter needed)
  • All 5 closeout fields must be true
  • orders.status = 'completed' on close
