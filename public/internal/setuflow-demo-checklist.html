STEP 1
Enter your name & start
Enter your name above and click "▶ Start Checklist". This creates a live run record in the database that tracks every item you check.
STEP 2
Work top to bottom
Work through each section in order — Pre-flight first, then Auth, Navigation, Leads, Quotes, Orders, PDFs, Admin, Mobile, Guru. Don't skip sections.
STEP 3
Pass / Fail / Block every item
For every item: open the CRM at the given route, perform the check, mark Pass, Fail, or Blocked. Add a note and upload a screenshot if it fails.
STEP 4
Add evidence on failures
When marking Fail or Blocked: click the item to expand it, add a note describing what you saw, and upload a screenshot. This auto-files a bug in the issue tracker.
STEP 5
Sign off at the bottom
When all items are checked, complete the sign-off form. A DEMO_READY or NOT_READY verdict is written to the database and linked to this run.
Rule: Every critical item (marked "Demo Blocker") must be Pass to proceed to a demo. A single blocker marked Fail means the demo should be postponed until the issue is resolved.

QUOTE PDF ✅
Working correctly
Must show: SETU Flow logo, org legal name, registered address, Tax ID, contact email. SELLER/EXPORTER box. BUYER/IMPORTER box. Line items table with HS codes, pricing basis, unit price, case price, totals. TERMS & CONDITIONS section with 5+ clauses.
ORDER PDF ⚠️
Confirm fixed status
SF-23-003/004 are open: Order Confirmation and Invoice PDFs do NOT include seller identity or T&C until fixed. Check: is SELLER/EXPORTER box populated? Are T&C present? If no → still broken → mark FAIL.
EMPTY ORDER
Guard check
SF-23-010: Order with no line items should return an error, not a blank PDF with "Order line pending" placeholder. Test this: create order, don't add lines, try to generate PDF. Should fail gracefully.
EVIDENCE
Always screenshot PDFs
For every PDF check — pass or fail — take a screenshot of the opened PDF and upload it as evidence. PDFs are the commercial face of the system and every test run should have proof of what was generated.
❌ NEVER
Skip the Pre-flight section
Pre-flight checks confirm the environment is clean and the test account is correctly set up. Skipping it means downstream failures may be environment issues, not product bugs.
❌ NEVER
Mark Pass without verifying
Do not mark Pass based on memory or assumption. Every item must be physically checked in the live system during the current run. Open the route, perform the action, confirm the result.
❌ NEVER
Demo with Critical blockers marked Fail
If any item marked "Demo Blocker" is Fail, the red banner at the top of this page shows the specific items. Proceeding with a demo while blockers are open risks destroying trust with the prospect.
❌ NEVER
Mark "sign out works" without testing it
SF-23-002 is open: sign out on desktop does not work. Do not mark this Pass until the fix is deployed and verified. Check: click header avatar → does a dropdown with "Sign out" appear?
SIGNAL 1
Clear next action visible
Every page in the CRM should tell the operator what to do next. Dashboard: follow-up queue. Lead detail: "Create quote" or blocker explanation. Order: stage strip shows active step.
SIGNAL 2
Blockers explain why
When a gate blocks progress, the message explains exactly what is missing and what action is needed. "Cannot proceed" without explanation is a failure state.
SIGNAL 3
Data write matches UI state
After every write (create lead, create quote, advance stage), the UI should update without a full page reload. If the action says "saved" but the UI doesn't reflect it → bug.
SIGNAL 4
link_created ≠ delivered
A WhatsApp link being created or a document link being generated is NOT confirmation of delivery. The system tracks link opens separately. Never conflate these two states.
