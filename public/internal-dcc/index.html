FlowBuild pathCritical handoff
Capture to leadAdmin Trade Events → Leads Quick Capture → Lead QueueEvent/source/product/follow-up values created at capture time.

Why Leads first: Leads owns capture, qualification, coverage, quote prep, and the first entry into Quote Builder. It is the root of most operator work.
Why Admin is next: Without Markets, Stages, and Pipelines configured in the admin, the operator cannot set up a workspace. This is a blocker for new customer onboarding.
Why Orders is first-class: Orders has a separate execution desk and state machine. It needs its own PR and its own compliance + dispatch readiness surface.

PR-NS-08 — Catalog-to-Quote Data Wiring Hardening

Pages affected: /products /leads/[id]/quote /quotes

Reference HTMLs: setuflow-catalog-redesign.html · setuflow-leads-redesign.html · setuflow-quotes-redesign.html

Required UI changes

  • Add pricing-tier selector to Quote Builder line item row (e.g. Ex-Factory / FOB / CIF) — pulled from product_prices.pricing_basis
  • Show missing-price warning badge on line item when no catalog price exists for the selected market + currency + pricing basis
  • Show override delta % indicator on line item when entered unit price differs from catalog baseline by more than org approval threshold
  • Ensure FX rate badge (7-day lock) displays on quote header in Edit and Revise flows, not only in Create flow
  • Duplicate quote flow must show source catalog context (product name, variant, catalog price ID, baseline amount) pre-populated and editable
  • Revise quote flow must re-evaluate catalog price freshness and surface a "Catalog price changed since last version" warning if baseline has shifted

Required workflow changes

  • Pricing tier selection must gate readiness: a line item with no price for the selected tier must show as blocked in the quote readiness check before send
  • Override approval threshold must be enforced in edit and revise flows — not only in create flow
  • FX lock from an existing quote version must be reused in revise flow, not re-fetched (preserves pricing continuity)
  • Duplicate quote must copy catalog_price_id, catalog_price_amount, catalog_price_currency, and pricing_basis per line item

Required data wiring changes

  • Quote wizard form must read product_prices.pricing_basis and surface it as a selectable field
  • Quote wizard form LineItemDraft type must add pricing_basis: string | null
  • Revise quote RPC (update_quote_with_line_items_and_fanout) must accept and persist pricing_basis per line item
  • Missing-price detection must query product_prices for matching (market, currency, pricing_basis) tuple
  • Duplicate flow must use create_quote_with_line_items_and_fanout with source line item data pre-populated

Required Supabase / schema changes

  • Add pricing_basis text column to quote_line_items if not already present — check migration 049
  • Add pricing_basis text column to contract_line_items if not already present
  • Index: CREATE INDEX IF NOT EXISTS idx_product_prices_market_basis ON product_prices(market_id, pricing_basis, currency);

Required component updates

  • quote-wizard-form.tsx — add pricing tier selector, missing-price badge, override delta %
  • quote-workspace.tsx — propagate catalog context into duplicate/revise flows
  • reference-quote-builder-flow.tsx — display FX badge in edit/revise
  • catalog-pricing-model.ts — add helper: getPricingTiersForProduct(productId, marketId, currency)

Definition of Done

  1. Pricing tier selector renders in Quote Builder line item row; selects Ex-Factory / FOB / CIF
  2. Missing-price badge appears when no catalog price found for (market, currency, tier) — blocks quote readiness
  3. Override delta % displays when unit price deviates beyond org threshold
  4. FX lock badge visible in Edit and Revise quote modes
  5. Duplicate quote carries all catalog_price_* fields and pricing_basis into new quote line items
  6. Revise quote detects catalog price changes since last version and surfaces a warning
  7. Override threshold enforcement active in edit and revise flows
  8. Vercel build passes; no TypeScript errors

Migration 107 — organization_id backfill

Run this in Supabase SQL editor. Safe: all operations use IF NOT EXISTS / DO NOTHING patterns.

-- =========================================================
-- Migration 107: Add organization_id to lead_markets,
-- lead_product_interests, and contract_line_items
-- Safe to run multiple times (idempotent guards in place)
-- =========================================================

BEGIN;

-- ─── 1. lead_markets ─────────────────────────────────────
ALTER TABLE public.lead_markets
  ADD COLUMN IF NOT EXISTS organization_id uuid
  REFERENCES public.organizations(id);

-- Backfill from parent leads table
UPDATE public.lead_markets lm
SET organization_id = l.organization_id
FROM public.leads l
WHERE lm.lead_id = l.id
  AND lm.organization_id IS NULL;

-- Make NOT NULL after backfill (only if all rows backfilled)
-- ALTER TABLE public.lead_markets
--   ALTER COLUMN organization_id SET NOT NULL;

-- Index
CREATE INDEX IF NOT EXISTS idx_lead_markets_organization_id
  ON public.lead_markets (organization_id);

-- RLS policy
DROP POLICY IF EXISTS lead_markets_org_isolation ON public.lead_markets;
CREATE POLICY lead_markets_org_isolation
  ON public.lead_markets
  FOR ALL
  TO authenticated
  USING (
    organization_id = (
      SELECT organization_id FROM public.organization_members
      WHERE user_id = auth.uid()
      LIMIT 1
    )
  );

ALTER TABLE public.lead_markets ENABLE ROW LEVEL SECURITY;
