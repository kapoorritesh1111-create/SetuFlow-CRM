Pipeline Redesign — Code Review & Builder Guide
The pipeline board is the best module in the system — the kanban pattern is correct and drag-and-drop works. These changes tighten the signal-to-noise on cards, add a slide-in detail panel, and remove the heavy prose layer that sits above the board. Consistent with dashboard and leads design system throughout.
1 — Above the board: what changed

❌ Current (too much reads before board loads)

1WorkspaceWorkflowShell (today filter + mode)
2"Where am I" / "What is blocking me" 2-panel prose
3PipelineAIStrip (AI message above board)
4CollapsiblePanel "Board status" with 3 StateMessages inside
55-column ToolbarStat row
6Filter panel (hidden by default)
7Lane summary grid (5 cards)
8Board (finally!)

✅ Proposed (stats → board immediately)

1Topbar (consistent, vCard + mode switch)
2Filter bar (search + 4 dropdowns, same as dashboard/leads)
36-stat strip with colour-coded KPIs + clickable
4Board — immediately visible
Why: The "Where am I" + "What is blocking me" boxes + AI strip + CollapsiblePanel with StateMessages = the operator reads ~200 words of internal documentation before seeing a single pipeline card. For a client demo this is fatal. The stats strip conveys the same information in 6 numbers.
2 — Lead card: signal reduction (most impactful code change)

❌ Current card — 8 visible elements

❌ Health badge (at_risk / healthy / stalled)
❌ Follow-up badge (with icon)
❌ Pricing readiness badge (ready / partial / missing)
❌ Move readiness box + next action label
→ AI suggestion text (full sentence)
→ Stage blockers list (rose box)
→ Action items pills (up to 2)
→ Coverage summary (sky box)
Result: 8-10 visual elements per card · impossible to scan across 20+ cards

✅ Proposed card — 4 elements + expand

✓ Company + flag + contact (always)
✓ 2 badges MAX: type pill + most urgent signal
✓ Move readiness bar (compact: ok / warn / blocked)
✓ 2 action buttons (advance or schedule)
→ Footer: owner + value/source
Blockers, AI guidance, coverage, history → click to open slide-in detail panel. Never on the card surface.
Builder note: In lead-card.tsx, remove suggestedAction div, visibleReadinessReasons block, visibleActionItems pills, and coverageSummary div from the card body. Move all of these into a LeadCardDetailPanel component that renders in the slide-in. The card click opens the slide-in, not the full command center.
3 — New component: slide-in detail panel
＋
New component
LeadCardDetailPanel (slide-in)
A 420px right-side panel that opens when a card is clicked. Shows: contact detail, status row, blockers, stage move selector, quick actions (schedule / note / open full record). Does not navigate away from the board. Escape key closes it. Click overlay closes it.
＋
New UX pattern
Stage move inside the panel
Instead of the move dropdown on the card (or in a card-opened inline form), stage moves happen inside the detail panel. The panel shows all stages with move-readiness state (ready/blocked/current). One click to move — no form, no dropdown.
✓
Keep
Drag-and-drop between lanes
The HTML5 drag-and-drop implementation is correct and needs no changes. The drop highlight (isActiveDropTarget) is good UX. Keep the readiness check on drop — blocking invalid moves via drag is important for governance. Just make the drag handle more visible.
✓
Keep & improve
Lane headers with signal counts
Lane headers showing overdue count + blocked count + value total is exactly right. Add pipeline value total ($) per lane — currently only shows count. This is the one number trading leadership looks at first. Add it with a thin separator line.
✕
Remove from board surface
PipelineAIStrip
The AI strip is positioned between the stats and the board and displays a generic AI message about overdue leads. This adds nothing a number doesn't already say. Remove from above the board. AI guidance moves into the slide-in detail panel as a "Next safe action" field per lead.
✕
Remove
CollapsiblePanel "Board status and route shortcuts"
This collapsible contains 3 StateMessage components and route links (Dashboard / Follow-up / Orders). The route links move to the page nav tabs. The StateMessage content moves to the 6-stat strip. The CollapsiblePanel is removed entirely — it adds a collapsible interaction before the operator can see the board.
4 — Filter bar: consistent with dashboard + leads
⟳
Move + restructure
Filters move from secondary panel to filter bar
Currently: filters are inside a `filtersOpen` collapsible triggered by a toolbar button. This is a second click before the operator can filter. New: all 4 filters (follow-up, owner, category, market) + search are always visible in the filter bar — same pattern as dashboard and leads pages.
＋
New
Active filter chips below filter bar
Same active-chip pattern from dashboard: "11 overdue ×" and "UAE ×" chips appear when filters are active. Clicking × clears that filter. Result summary "47 leads · $1.2M" is right-aligned. This replaces the verbose "active filter count" badge on the toolbar button.

Builder sprint plan — Pipeline page
Sprint 1 (quick — 1 day): Remove AI strip from board · Remove "Where am I" prose boxes · Remove CollapsiblePanel · Replace with 6-stat strip. Board appears immediately on load. This alone transforms the demo experience.

Sprint 2 (core — 2 days): Add LeadCardDetailPanel slide-in · Simplify lead card to 4 elements · Move blockers/AI/coverage into the panel. Stage move selector inside the panel replaces the card's move dropdown.

Sprint 3 (polish — 1 day): Flatten filter bar (always visible, consistent with dashboard/leads) · Add pipeline value ($) to lane headers · Add active filter chips. The board now feels like part of the same product family.

Drag-and-drop: Keep exactly as-is. The HTML5 DnD implementation is solid. The readiness gate on drop is important for trade governance — do not remove it. Just make the drag cursor more obvious (use a grab cursor CSS + drag ghost opacity).
