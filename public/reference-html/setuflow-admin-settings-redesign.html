SETU Flow — Admin + Settings Redesign
Admin + Settings redesign · combined workspace · Phase 1
Admin + Settings Redesign — Code Review & Builder Guide
7 separate pages (/admin/organization, /admin/users, /admin/invitations, /admin/audit, /admin/ai-analytics, /admin/product-management, /settings/lists) collapse into one "Workspace Control" workspace with a left navigation rail. This is the most impactful structural change in the system — it reduces navigation jumps from 7 to 0.
1 — Navigation collapse: 7 pages → 1 workspace

❌ Current — 7 separate pages (scattered)

1/admin/organization
2/admin/users
3/admin/invitations
4/admin/audit
5/admin/ai-analytics
6/admin/product-management
7/settings/lists

✅ Proposed — 1 workspace (9 sections, left nav)

→/admin → Organization overview
→/admin?section=team → Team members
→/admin?section=invites → Invitations
→/admin?section=markets → Markets & Countries
→/admin?section=categories → Product categories
→/admin?section=nextsteps → Stages & next steps
→/admin?section=pipelines → Pipelines
→/admin?section=audit → Audit log
→/admin?section=security → Security & roles
Builder implementation: Create a single /admin/page.tsx that reads ?section= from searchParams. Each section renders its own component. The left nav is a new AdminSideNav component. The /settings/lists route redirects to /admin?section=markets. Remove the separate "Settings / Lists" nav item from the sidebar entirely.
2 — Governance banner: always visible, actionable
＋
New
Governance banner at top of all admin sections
Current: governance gaps are only visible on the organization page, buried under StatCards. New: a banner appears at the top of every admin section when gaps exist. Each gap item is a clickable chip that navigates to the right section to fix it. Banner disappears when all gaps are resolved.
⟳
Fix
Approval threshold — from invisible to mandatory field
Currently the approval threshold is configured somewhere in the system but not clearly surfaced. New: it lives in Organization overview as a required input field, and appears in the Security section. If unset, the governance banner flags it as a critical gap that must be resolved before demo.
3 — Reference lists: inline add/edit (no separate drawers)
⟳
Redesign
SettingsListsManager — collapse 4 expandable sections
Current: markets, countries, next steps, and product categories each have an expandable accordion. This collapses/expands is unnecessary — each list is short enough to show inline. New: Markets & Countries in a 2-column layout. Categories and Stages in their own sections. Edit inline, save inline. No separate drawer needed.
＋
New
Drag-to-reorder for list items
Sort order matters for pipeline stages and next steps. Add drag handles (⋮⋮) to every list item. The drag-and-drop reorders and saves sort_order to the database. Builder: use the native HTML5 draggable API — same pattern already used in the pipeline board.
✓
Keep
Export/import snapshot
The importSettingsListsSnapshot and export JSON feature is excellent for setup and migration. Keep it. Add an "Export config" button to the topbar that exports all reference lists as a JSON snapshot. Useful for client setup and config backup.
✕
Remove
AI governance panel from settings manager
AICompactActionBrief appears inside SettingsListsManager. This is a governance tool — it has no place in the list editor. The AI analytics summary moves to its own dedicated section (AI Analytics) with usage stats. Remove from settings-lists-manager.tsx entirely.
4 — Audit log: unified, filterable, always accessible
⟳
Improve
Audit log with 3 category filters
Current: 4 view options (all / catalog / leads / access). New: simpler filter row with dropdowns for category, actor, and time range. Result: faster to answer "who changed this product's price last week?" without navigating to a specific view. The category filter maps directly to existing AuditViewKey type.
＋
New
Audit trail visible from any admin section
When viewing Team Members, a "See audit trail for access events →" link takes you to the audit section pre-filtered to "Access + roles". Same pattern for Catalog and Leads sections. Deep linking via ?section=audit&category=access. Keeps audit in one place but makes it reachable contextually.
⚙
Builder sprint plan — Admin + Settings
Sprint 1 (structural — 2 days): Create single /admin/page.tsx with section routing · Build AdminSideNav left nav component · Redirect /settings/lists → /admin?section=markets · Remove "Settings / Lists" from sidebar nav. This is the entire structural change.

Sprint 2 (governance — 1 day): Build governance banner component (reads buildAdminGovernanceContext output) · Make approval threshold a visible required field · Add governance banner to all sections.

Sprint 3 (list UX — 1 day): Inline add/edit for all reference lists (no separate drawers) · Add drag handles for sort order · Move AI analytics out of settings into its own admin section · Remove AICompactActionBrief from SettingsListsManager.

Net result: Admin goes from the most confusing navigation in the app (7 pages, 2 sidebar items) to the clearest (1 workspace, 9 sections, left nav). Client demo can walk through the entire admin setup without a single page refresh.
