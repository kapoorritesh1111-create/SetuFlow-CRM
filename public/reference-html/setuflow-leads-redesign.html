Leads page redesign · for builder handoff
Leads Page Redesign — Code Review & Builder Guide
Two surfaces redesigned: the Lead Queue (list view) and the Lead Command Center (individual lead). Every change maps to an existing component in the codebase. Consistent with the dashboard design system.
1 — Lead queue: what changed in the list view

❌ Current (cognitive overload)

1StateMessage (mode explanation)
2LeadsWorkspace (1,456 lines, everything visible)
36 signal pills per lead row
4AI brief sentence on every row
5Batch controls always visible
6No visual hierarchy between urgent/normal leads

✅ Proposed (action-first)

1Saved views bar (always visible, no StateMessage)
2Sectioned rows: Critical → Due today → Active
32 signal pills max per row (type + stage only)
4Left accent bar = severity (rose/amber/emerald)
5Batch controls only appear after checkbox selection
6AI brief removed from rows — moved to Command Center
2 — Command Center: workflow panel redesign
✓
Keep & elevate
LeadPipelineStageStrip
The stage strip is excellent. Visual state (done/current/upcoming) is clear. Add: clickable upcoming stages trigger a confirmation tooltip before moving. Remove the wall of detail text that appears on click — keep it compact.
✓
Keep & elevate
QuotePrepChecklist
This is the best UX concept in the system — a visual readiness checklist before quote creation. Keep it, make it the primary focus below the workflow pillars instead of hiding it behind the WorkflowTab structure.
＋
New pattern
4-pillar workflow cards
Replace the WorkflowTab accordion with 4 visible cards (Follow-up, Qualification, Coverage, Commercial). Each shows current state at a glance. Click opens the panel inline below — no page switch, no deep nesting.
＋
New pattern
Inline panel host (no drawers)
Workflow detail opens inline between the pillars and the checklist — not in a side drawer. This means the operator never loses page context. Only one panel open at a time. Close returns to the pillar grid view.
⟳
Restructure
LeadCommandHeader — strip status chips
Currently shows 3 chips in a row above the company name. Problem: "Pricing partial" and "Compliance clear" mean nothing without context. Fix: make each chip clickable, opening the relevant workflow panel directly. Add urgency colour (rose for overdue chip).
⟳
Restructure
SupportingRecordPanel simplification
Currently: "Supporting record stays collapsed until the blocker is explicitly inspected" — this is developer language shown to users. Fix: rename to "Lead log" and "Quote record". Remove the prose explanation entirely. Toggle with simple tabs at the bottom of the page.
✕
Remove
StateMessage on command center
"Stay in this command center until qualification, coverage, and next action are explicit." — an operator who opens a lead does not need to be told why they're there. Remove this entirely. The QuotePrepChecklist communicates this more effectively through action items.
✕
Remove / demote
LeadAiAssistPopover from primary actions
AI popover is currently triggered from the header action row alongside "Create quote". This competes with the primary action. Move it to the "Lead tools" dropdown menu. AI assist stays accessible but does not compete with the commercial CTA.
3 — Add Lead drawer: what changed
＋
New
Type switch — Buyer vs Supplier at top
Current: lead type is a dropdown buried in the form. New: large toggle at the top of the drawer. This changes which fields appear and which pipeline is pre-selected. Reduces friction for the most common trade-show fast-lane use case.
＋
New
Product pre-selection in the add form
Products of interest can be selected at creation time (not after). This removes the separate "Coverage" step for most leads. Show common products as quick-tap chips so the trade-show operator can capture a lead in under 60 seconds.
⟳
Improve
"Auto-advance to quote" option
The existing initialQuickCapture.autoOpenQuoteAfterSave prop is already implemented but invisible to the user. Expose it as a visible toggle in the drawer: "Open Quote Builder after saving this lead?" This saves the double-navigation for qualified inbound leads.
⟳
Improve
Follow-up date in the add form
Current: follow-up must be set after creation, inside the command center. New: set it during lead creation. For trade-show leads especially, the operator knows immediately when to follow up. One less step after saving.
4 — Cross-page consistency with dashboard
✓
Consistent
Topbar — same structure as dashboard
Company badge · vCard button · mode switch (All/Buyers/Suppliers) · Quick Lead · avatar. Identical position and style across both pages. Builder can reuse the topbar component with zero changes.
✓
Consistent
Filter bar — identical pattern
Same filter-select-wrap components, same active-chip pattern, same result-summary right-aligned. Filter bar is a shared component between dashboard and leads. Add: "Follow-up timing" filter (Overdue / Today / Upcoming / All) — leads-specific.
✓
Consistent
Design tokens — same colours, radii, shadows
All CSS variables match the dashboard exactly: navy, brand blue, slate scale, emerald/amber/rose semantic colours. Section cards, pills, avatar styles are identical. Build once, apply everywhere.
＋
New addition
Blue Orbit company badge in topbar
Added to both dashboard and leads topbar: BO mark + company name + "SETU Flow CRM" sub-label. Appears left of the page title. Reinforces brand identity for client demo without cluttering the nav. Implemented as a shared CompanyBadge component.
🎯
Builder checklist — what to implement first
Sprint 1 (quick wins): Add left-accent severity bar to lead rows · Section rows into Critical/Today/Active · Move batch toolbar to appear on checkbox · Remove StateMessage from Command Center · Add Blue Orbit company badge to topbar.

Sprint 2 (structure): Replace WorkflowTab accordion with 4-pillar card grid · Build inline panel host (no drawers) · Move AI assist to tools dropdown · Make header status chips clickable.

Sprint 3 (add lead UX): Buyer/Supplier toggle at top of drawer · Product pre-selection chips · Follow-up date in creation form · Auto-advance to quote toggle.

Always consistent: Every page uses the same topbar, filter bar, mode switch, section-card pattern, and pill components. Build them as shared components from day one.
