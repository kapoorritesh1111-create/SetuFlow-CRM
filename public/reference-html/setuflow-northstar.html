Critical paths — workflows that must never break
⚡ 6 critical paths — every blocker, gate and hand-off
Path 1 — Trade show capture (60 seconds)
vCard scan → ◎ Quick Lead drawer → Lead queue
Buyer/Supplier toggle → product chips → follow-up date → save. Must be completable in under 60 seconds on mobile. No required fields except company name.
⚠ Gate: Drawer must open from topbar in every page
Path 2 — Follow-up to first quote
◎ Command Center → 4 pillars green → ◇ Quote Builder
All four workflow pillars (Follow-up, Qualification, Coverage, Commercial) must be complete before the Create Quote CTA activates. Quote prep checklist is the visual gate.
⚠ Gate: Quote blocked until qualification + coverage done
Path 3 — Pipeline stage advance
⊕ Card drag → Readiness check → Stage confirmed
DnD triggers buildStageMoveReadiness(). If canMove is false, drop is blocked and message shown. Overdue follow-up always blocks advancement. This governance must never be bypassed.
⚠ Gate: Follow-up overdue blocks ALL stage moves
Path 4 — Catalog → Quote pricing pre-fill
▦ Baseline price set → Lead coverage maps product → Quote pre-fills
When a quote is opened, the USD catalog baseline price is automatically loaded and converted into the selected quote/company currency through a weekly FX lock. Any manual price override requires a reason and approval-threshold governance still applies.
⚠ Gate: Missing USD catalog price or missing FX rate blocks converted quote price
Path 4B - Quotes Workspace operating view
Quote table → Detail panel → Approval / revise / send
Quotes now follow the Quotes redesign HTML: mode switch, Export, + New quote, filter bar, KPI cards, approval queue banner, selectable table rows, row actions, detail approval gate, line items, locked FX context, override reasons, Create order, Export PDF, and version history in one workspace. Quote Builder creates and edits; Quotes Workspace operates the lifecycle.
⚠ Gate: No send without clear approval status and visible pricing context
Path 5 — Admin reference lists → everywhere
⚙ Admin markets → Catalog dropdowns + Lead coverage + Pipeline lanes
Markets, categories, stages, next steps — all defined in Admin. These feed every dropdown across all pages. Admin must be configured before any other workflow can function correctly.
⚠ Governance: Admin must be set up FIRST in any new workspace
Path 6 — Approval threshold enforcement
Quote pricing override → Threshold check → Approve / block
Any pricing override above the Admin-configured threshold (e.g., 10%) must trigger an approval request. Without the threshold set in Admin Security, all overrides bypass governance.
⚠ Critical: Threshold must be set before first quote is sent

Product Category Schema — PR-NS-11 · Multi-category expansion
🗄 SCHEMA REQUIREMENT — category_type must support all 7 product families
!
Current constraint is too narrow. Both pricing_rule_set_items and quote_line_items only accept 'chips' | 'powders'. Blue Orbit International has 7 product families. Any quote for sweeteners, onion, garlic, or freeze-dried products will violate DB constraints at the line-item level.
✓
Migration 057 is ready: mitigation/supabase/sql/057_expand_category_type_constraint.sql. Expands constraint to: chips · powders · sweeteners · onion · garlic · freeze_dried · other. Run in Supabase SQL editor. No data loss.
→
product_categories table: New column category_type (nullable text, same CHECK). Backfill via pattern matching on existing category names. Set on all new categories via CategoryForm selector.
→
Category-type derivation chain: quote line items derive category_type from: product_id → products.category_id → product_categories.category_type. Fallback: 'other' (not 'chips'). This is the correct default — unknown categories should not be silently mis-classified as chips.
→
UI requirement: CategoryForm must render a dropdown with all 7 values and human-readable labels: "Chips (Vacuum-Cooked)", "Powders (Dehydrated/Spray-Dried)", "Sweeteners", "Onion Products", "Garlic Products", "Freeze-Dried", "Other".
→
Pricing rules: PricingRuleSetItem.category_type TypeScript union must include all 7 values. Pricing rule queries must not silently filter to only chips/powders.
