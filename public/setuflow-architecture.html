Setu Flow Architecture Summary

This page summarizes the current architecture and readiness posture in buyer-safe language. For internal readiness and proof tracking, use public/internal-dcc/index.html.

What Setu Flow is

Setu Flow is a trade-focused CRM and execution workspace for import-export teams. It is designed to preserve commercial truth from lead creation into quoting, contracts/orders, and execution.

Premium mobile direction

SETU Flow now has a mobile-first premium blueprint for field work: branded app shell, buyer and supplier capture, quick quote, role-aware current leads, and light/dark mobile appearance. The mobile path is additive and does not change the existing desktop routes.

Mobile Leads Buyer / Supplier Quick Quote Light / Dark

Architecture layers

  • Next.js app shell for route composition and product surfaces
  • Feature domains for leads, pipeline, quotes, contracts, orders, AI, and integrations
  • Shared workflow library for pricing, approvals, continuity, and execution logic
  • Supabase for data persistence and application state

Current strengths

  • Real buyer/supplier/product/quote data exists in the workspace
  • Catalog-aware pricing and approval policy are part of the product design
  • Contract/order continuity is partially visible in live data
  • Execution controls exist structurally in the repo

Current limitations

  • Accepted quote truth is not yet fully reconciled across all surfaces
  • Approval-required quote examples are not yet strongly surfaced in demo data
  • Execution proof is still draft-heavy in visible contracts
  • Integration maturity should be described conservatively

Mobile App v1 real routes

SETU Flow Mobile includes an isolated premium mobile route group behind feature/mobile_app_v1: Home, Leads, Quote, Capture, Notifications, and Settings.

The canonical /leads app route also renders the premium mobile lead queue on phone viewports, while desktop widths continue to render the existing desktop Leads workspace unchanged.

The mobile Leads screen keeps Share vCard and a visible signed-in user summary so field users know who is operating before they act on leads.

Role-aware visibility is enforced before render: owners and admins see all leads, managers see their teams and direct reports, and members see only assigned leads.
