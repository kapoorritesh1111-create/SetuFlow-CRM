# Setu Flow Mobile 2.1 — Capability Matrix & Locked Design Contract

**Assessment date:** 2026-10-11. **Audited GitHub main:** `0e16c1de9f5c0dade260defa44d4a45388ebacd5`. **Live Stark Packmate org:** `b97913cb-3b95-4247-8ced-ffdc0d392d2a`. This is a source/schema review, NOT completed hands-on device QA for each route.

## Scope, rules and status legend
Status MOBILE = actual mobile component/flow source inspected; PARTIAL = mobile entrypoints or shared pages exist but full workflow and 375px usability not verified; DESKTOP = existing desktop route with no validated purpose-built mobile experience; PARALLEL MOBILE WORKSTREAM = separate mail PWA implementation. Offline behavior is **unverified unless specifically cited**; source queue implementation is not equivalent to successful device QA.

**Non-negotiables:** Preserve Mobile 2.0 visual direction, five-tab maximum, light/dark/system, role and org module entitlement and least privilege, no fake metrics, no duplicated actions on Home/bottom tabs, shared backend/auth, no disabled modules appearing, no blanket mobile access on empty grants, separate Setu Mail PWA, no desktop regression, no repeated production deployments. User role is a recommended policy to validate against actual RLS and existing actions, NOT a claim that every listed role restriction was proven by this audit.

**Stark Packmate live grants**: analytics=true; full_crm=true; orders_compliance=false; setu_guru=true; setu_mail=false; trade_show=true; vcard=true. Supplier procurement has no explicit grant row; entitlement fallback is a release risk. Treat absent grant as unresolved—not automatically enabled for mobile.

**Observed repo defects:** `src/features/mobile/components/mobile-bottom-tabs.tsx` selects static nav items; `src/lib/navigation/nav-items.ts` includes Orders and Mail statically; `src/features/mobile/components/mobile-navigation.tsx` hardcodes Scan Card/Trade Show/Quotes/Orders Home shortcuts and order/compliance KPI; `src/components/shell/navigation.tsx` has grant-filter path; `src/lib/modules/module-grants.ts` defaults almost all modules on empty/missing grant; `src/app/api/modules/grants/route.ts` can return all module keys without a workspace. MUST inspect server route/actions and RLS before changing contract, not just hide UI.

**Design decision:** My Workspace (role/task-focused) + Admin Command Center (owner/admin low-risk actions) + desktop Advanced Setup (complex/high-risk), with internal SMC fully separated. Admin is a permissioned More/profile destination, not a fixed universal tab. 5 bottom tab slots should be adaptive yet stable by role. Home shows 3 compact permissioned KPIs, Guru priority and next actions; do not duplicate primary tabs in quick actions.
