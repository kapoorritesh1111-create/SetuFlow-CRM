# Mobile Promise Alignment

Updated: 2026-04-30  
Baseline: PR-NS-21 Mobile promise alignment

## Executive truth

SETU Flow should be described as **desktop-first CRM operations with selected mobile-friendly capture flows**, not as a fully mobile-native CRM.

## Supported claims

| Claim area | Honest wording after PR-NS-21 |
|---|---|
| Mobile use | Selected flows are phone/tablet-friendly, especially trade-event lead capture and lightweight review moments. |
| Responsive shell | The app shell includes responsive/mobile layout work and PWA install metadata, but this does not prove every workflow is mobile-optimized. |
| Offline | Offline support is scoped to trade-event lead capture queueing and sync. It is not a general offline CRM mode. |
| Desktop | Full CRM operations, quote authoring/editing, order execution, admin, and investor demo navigation remain desktop-first. |
| Investor demo | Use desktop for the full golden revenue handoff. Mobile may be shown only as an adjunct capture wedge where verified. |

## Claims to avoid

- Fully mobile-native CRM.
- Every SETU Flow workflow works offline.
- Phone-first quote/order execution is proven.
- Mobile app parity is complete.
- The entire buyer journey can be completed on mobile.

## Buyer demo language

Use:

> SETU Flow is desktop-first for core CRM, quote, and order execution. The mobile-friendly wedge is trade-event capture: reps can capture buyer or supplier leads on phone/tablet, including a scoped offline queue for lead capture only.

Avoid:

> SETU Flow is fully mobile-native and works offline end-to-end.

## Investor script language

Use:

> The proven revenue path is desktop-first today: Q-00025 is accepted and linked to draft order execution with 11 lines. Mobile is positioned honestly as a targeted capture wedge, not full workflow parity.

## Verification note

PR-NS-21 did not add mobile features. It aligned claims, docs, DCC language, and a small trade-event capture drawer copy string so the product promise matches verified behavior.
